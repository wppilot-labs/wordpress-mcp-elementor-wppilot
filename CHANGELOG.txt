v1.1.0 - unreleased
* WordPress core abilities now ship in WPPilot Free. Content, taxonomies, media, comments, revisions, menus, user reads, and the allowlisted settings surface work with Free alone, with no Pro plugin, licence, or entitlement service involved. Pro remains the home of plugin-aware integrations: page builders, WooCommerce, forms, SEO suites, custom fields, themes, and multilingual.
* Added terms and taxonomies: discovery, listing, reading, creation, updates, confirmed deletion, and assignment to content, each enforcing the taxonomy's own manage_terms/edit_terms/delete_terms/assign_terms capability rather than assuming manage_categories.
* Added comments: listing and reading with commenter email and IP withheld from accounts that cannot moderate, plus creation, editing, approve/hold/spam/unspam/trash/restore moderation, and confirmed permanent deletion.
* Added revisions: listing with autosaves distinguished from saved revisions, reading with a direct comparison against the live post, and restoration recorded as a reversible write.
* Added menu containers and placement: create, rename, confirmed deletion, theme-location listing and assignment, and whole-menu reordering validated before any item moves.
* Added featured-image set/remove and media attach/detach.
* Added post restoration from the trash, reporting the status WordPress actually restored to.
* Free ability count is now 92, up from 42.
* Security: create-post, update-post, and delete-post previously ran on a single manage_options check and never consulted the post type's own capability object. They now enforce create_posts, publish_posts, edit_others_posts, edit_post, and delete_post read from the registered type, so a custom post type declaring its own capability set is no longer satisfied by edit_posts, and object ownership is honoured.
* Security: menu item URLs are validated against WordPress's allowed protocols before storage. A javascript:, data:, or vbscript: URL was previously stored verbatim and rendered into an href.
* Draft-first content creation is enforced in code rather than by schema default alone. Absent, blank, mistyped, and unrecognised statuses all resolve to draft before the capability gate reads them, so content cannot be published by omission or by a malformed value through any entry point.
* Generic content wrappers now refuse internal and plugin-private post types and taxonomies, so agents cannot write rows the owning subsystem never validates.
* Change ledger covers the new mutations, with before-images and verified rollback for term edits, comment edits and moderation, menu location assignment, and menu ordering. Permanent term, menu, and comment deletions are recorded as non-reversible with the reason stated.
* Added the repository's first automated test suite: unit tests running against WordPress function doubles, with no database required.

v1.0.0 - 2026/08/08
* Initial public release.
* MCP server for WordPress, built on the WordPress Abilities API and the official MCP Adapter.
* Two ways in: OAuth 2.1 with PKCE and dynamic client registration, or WordPress application passwords.
* Generated connection configuration for Claude Code, Claude Desktop, Codex, Cursor, VS Code, GitHub Copilot, Antigravity CLI, Antigravity IDE, Windsurf, Zed, Cline, Roo Code, Kilo Code, Amazon Q, and OpenCode.
* Overview screen showing which AI clients are connected, how they authenticated, and how much they call.
* Safety profiles — Production Safe, Read Only, and Developer Full Access — enforced across ability registration, MCP dispatch, and direct REST execution.
* Destructive and critical operations require explicit confirmation, and supported mutations are recorded in a bounded, redacted change ledger with verified rollback.
* Per-credential rate limiting on ability execution, with read-only abilities exempt.
* Typed content, media, users, settings, extensions, navigation, and diagnostics operations, so raw developer primitives are rarely needed.
* Skills, site instructions, and a sandbox for agent-authored PHP, isolated behind directory guards.
* Diagnostics screen that probes the connection the way a client does and names what to fix.
* MCP and WPPilot REST responses validate the request host and send no-store security headers.

Releases before 1.0.0 were internal and are not part of the public history.
